Ask a statistical question about 1.85M Goodreads editions.

A model chooses the tool and writes the explanation. It does not write the numbers: every figure below is rendered from the tool's own JSON, together with the count it rests on, the unit one row counts, what the minimum-ratings threshold excluded, and the caveats attached to the specific columns they weaken.

  • The tool call is shown in full — name, parameters, bytes billed, cache hit or miss, and the BigQuery share of the wall time.
  • A refused call is a result, not an error. Asking for something the dataset cannot support tells you why it cannot.
  • A checker marks any numeral in the prose that does not appear in a tool result, so the interface's central claim is verifiable rather than asserted.

Call a tool directly. No model in this path.

Pick one of the server's tools and fill in its parameters. The result is rendered by exactly the same code the chat mode uses — the same n, unit and threshold block, the same caveats attached to the columns they weaken, the same charts, the same refusal cards. Nothing here is interpreted, because nothing here is generated.

  • The form is built from each tool's own JSON Schema, fetched over MCP. Every label, range and default below is the server's, not this console's.
  • A field left empty is not sent, so the card's parameter row shows exactly what you overrode. Defaults are printed beside each field.
  • Values are passed verbatim. A parameter the server refuses returns its refusal, with the reasoning behind the constraint — that is a result worth seeing, so nothing is corrected on the way in.
